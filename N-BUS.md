================================================================================
  СПЕЦИФИКАЦИЯ СЕТЕВОГО ПРОТОКОЛА РАСПРЕДЕЛЕННОГО ЧПУ: N-BUS (v1.0)
================================================================================
Назначение: Асинхронный межузловой обмен жесткого реального времени (Hard Real-Time)
Базовая программная платформа: Экосистема ядра ЧПУ grblHAL
Физический уровень передачи данных: Изолированная шина CAN FD
Базовая тактовая частота периферии CAN FD: Строго 80.0 МГц
Скорость шины: 1.000 Мбит/с (Арбитраж) / 4.000 Мбит/с (Data Phase Switch)
================================================================================

1. ФУНКЦИОНАЛЬНОЕ РАЗДЕЛЕНИЕ ДОМЕНОВ (СЕТЕВАЯ ТОПОЛОГИЯ)
Протокол N-Bus базируется на использовании трех независимых и аппаратно 
изолированных друг от друга каналов связи (доменов) на стороне главного 
маршрутизатора ЧПУ, тактовые частоты которых выровнены на уровне ФАПЧ до 80.0 МГц:

* CAN FD1 (Силовой домен перемещения): Выделенная скоростная магистраль 
  взаимодействия с контроллерами исполнительных осей ЧПУ.
* CAN FD2 (Технологический домен телеметрии): Выделенный изолированный канал 
  для сбора данных с измерительных узлов и периферии рамы станка.
* CAN FD3 (Периферийный резерв): Зарезервированный свободный сетевой канал 
  для подключения внешних систем автоматизации общего назначения.

2. ДВУХФАЗНЫЙ РЕГЛАМЕНТ СИНХРОНИЗАЦИИ ШИНЫ (КВАНТ ВРЕМЕНИ 0.5 мс)
Межузловой обмен внутри домена CAN FD1 подчинен жесткому циклическому графику 
с квантованием времени 2 кГц (один шаг планировщика — строго 500 микросекунд). 
Для полной ликвидации временного джиттера передача данных разделена на две фазы:

* ФАЗА А (РЕЖИМ ПОДГОТОВКИ / ПУБЛИКАЦИЯ):
  Центральный контроллер последовательно публикует в шину индивидуальные бинарные 
  кадры с целевыми координатами для каждого исполнительного привода осей 
  (например, ID 0x101, ID 0x102...). Узлы принимают пакеты, проводят валидацию, 
  но не начинают отработку движения, удерживая значения в буфере Next Target.

* ФАЗА Б (РЕЖИМ ВЫСТРЕЛА / АППАРТНЫЙ ТРИГГЕР):
  Маршрутизатор выстреливает в сеть пустой высокоприоритетный кадр SYNC_PACKET 
  с идентификатором ID 0x000 и Data Length Code (DLC) = 0. Прием этого фрейма 
  обрабатывается контроллерами CAN всех узлов шины аппаратно. 
  В эту же микросекунду исполнительные привода одновременно переносят данные 
  из буфера ожидания в свои локальные контуры регулирования. Временной 
  рассинхрон выполнения шагов осей в физическом пространстве равен нулю.

3. ПРОТОКОЛ БАРЬЕРНОЙ ИНИЦИАЛИЗАЦИИ БЕЗОПАСНОСТИ
Для защиты механических узлов от повреждения при сбоях связи, протокол N-Bus 
запрещает циклическую передачу тяжелых калибровочных данных во время движения:
* Все статические таблицы коррекций и конфигурационные параметры передаются 
  монолитным бинарным блоком (Burst Transfer) строго один раз в момент подачи 
  питания на систему (Холодный старт).
* До успешного окончания передачи всего объема данных и верификации контрольных 
  сумм, центральный контроллер ЧПУ удерживает аппаратную линию безопасности 
  READY в состоянии LOW (0). Силовые каскады исполнительных приводов наглухо 
  обесточены. Перевод линии READY в состояние HIGH (1) и старт движения осей 
  разрешается только после получения подтверждений от всех узлов шины.

4. АППАРАТНЫЙ КОНТРОЛЬ ЦЕЛОСТНОСТИ СЕТИ (ROLLING COUNTER)
* В каждом циклическом кванте времени (2 кГц) центральный контроллер вместе 
  с координатами уставки инжектирует в шину инкрементный проверочный байт 
  (Rolling Counter, циклический счетчик от 0 до 255).
* При физическом повреждении линии связи или потере пакетов из-за помех, 
  принимающий исполнительный узел локально фиксирует застывание или пропуск 
  счетчика Rolling Counter на протяжении 2-х тактов подряд (1 миллисекунда).
* Узел мгновенно блокирует силовые выходы, выполняет экстренный останов 
  и выставляет в сеть флаг аппаратной аварии DRIVE_ERROR, инициируя сброс 
  общей линии READY в ноль.

5. УДАЛЕННОЕ УПРАВЛЕНИЕ КОНФИГУРАЦИЕЙ ЧЕРЕЗ grblHAL
* Протокол исключает необходимость физических переключателей настроек на узлах.
* Кастомный программный плагин расширения парсера ядра grblHAL перехватывает 
  текстовые сервисные конфигурационные параметры ЧПУ (например, $-команды), 
  вводимые оператором с ПК, и автоматически транслирует их в шину N-Bus 
  в виде бинарных пакетов во время фазы барьерного старта.
